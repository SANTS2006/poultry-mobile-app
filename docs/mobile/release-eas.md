# Mobile release: EAS, Android and iOS

The app is Expo SDK 57 (React Native 0.86, New Architecture). Native code is generated by Expo prebuild; `ios/` and `android/` are not committed. Configuration lives in `mobile/app.json` and `mobile/eas.json`.
**Verified**: TypeScript, lint, Jest, and Metro/Hermes bundles for Android and iOS. **Not verified**: any EAS cloud build, installation on a device, store submission, or push delivery.

## One-time setup (needs accounts)
1. Accounts: Expo (free is fine to start), Google Play Console (one-off fee), Apple Developer Program (annual fee). Choose the organisation names carefully; bundle ids are permanent.
2. `cd mobile && npm ci && npx eas-cli@latest login && npx eas-cli@latest init` → writes the real project id; put it in `app.json → expo.extra.eas.projectId` (currently `REPLACE_WITH_EAS_PROJECT_ID`; push registration refuses to run until replaced).
3. Set the real API URLs in `eas.json` (currently `https://staging-api.example.invalid` / `https://api.example.invalid`). Release builds refuse non-HTTPS URLs.
4. Bundle identifiers are `com.makarifor.poultry` (iOS and Android) — change before the first store upload if you own a different reverse-domain.
5. Push: `eas credentials` → upload FCM v1 service-account key (Android) and let EAS manage the APNs key (iOS). Optionally enable Expo “enhanced push security” and put the access token in the server’s `PUSH_NOTIFICATION_CONFIG`.
6. iOS: set `submit.production.ios.ascAppId`; Android: create the app in Play Console and add a service-account key for `eas submit`.
7. GitHub → repo secret `EXPO_TOKEN`; environments `preview` and `production` (with required reviewers on production) for the `mobile-eas` workflow.

## Build profiles (`eas.json`)
| Profile | Use | Output |
|---|---|---|
| `development` | dev client (SQLCipher, biometrics and push need it; **Expo Go cannot run this app**) | internal APK / simulator build |
| `preview` | staging API, testers | internal APK; iOS ad-hoc/TestFlight |
| `production` | store | AAB + IPA, `autoIncrement` build numbers, OTA channel `production` |

Commands: `eas build --profile preview --platform android`, `eas build --profile production --platform all`, `eas submit --profile production --platform all`. OTA JS updates: `eas update --channel production` (only JS/asset changes; native changes need a new build; keep `runtimeVersion` policy in mind before enabling updates).

## Store listing / privacy answers (draft — verify against the final build)
- **Data collected** (linked to the user, for app functionality only): name, email, phone (staff and customers entered by staff), business/financial records (sales, expenses), device push token, device name/platform, IP address (security logs). **No** advertising, tracking, analytics SDKs or location.
- **Data in transit/at rest**: TLS; database encrypted by the provider; local database encrypted (SQLCipher).
- Encryption exemption: the app uses standard HTTPS/TLS only (`ITSAppUsesNonExemptEncryption=false` is set; confirm with your export-compliance advisor).
- Permissions: notifications (`POST_NOTIFICATIONS`), biometrics (`USE_BIOMETRIC`, Face ID string). No camera, contacts, location or storage permissions.
- A public **privacy policy URL** and a **support contact** are required by both stores; they do not exist yet.
- Play Console also asks for a data-deletion process: document “ask your administrator to disable the account; business records are retained for legal reasons”.

## Known gaps
No app-store screenshots, icons are the Expo template placeholders (replace `assets/images/*` with brand artwork before release), English only, phone layouts only, no crash reporting (add Sentry or EAS Insights if wanted — it will need a privacy-policy update).
